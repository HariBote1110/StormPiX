# 資産変換レポート CLI

## Decision

- PNGフレーム列の入力複雑度と変換結果を、機械可読な JSON で出力する `stormpix report` を追加する。入力のサイズ、全体・フレーム別色数、隣接フレームとの差分画素数、スクリプト別文字数、フレーム範囲、品質指標を同じレポートへ記録する。
- `stormpix verify` は文字数不変条件、必要に応じた完全一致、予算内、総文字数上限を判定し、失敗時は非ゼロ終了する。CIでは `--max-total-chars` を資産ごとの回帰上限として指定する。
- 変換の検証対象は、入力資産をパスではなくレポートに明記したため、`/Users/yuki/doc/*` のようなローカル資産でも再現可能な比較条件を残せる。

## Alternatives considered

- ベンチ出力の人間向け表だけを拡張する案は、CIの閾値判定と変更前後の構造比較に向かないため採用しない。
- 実アセットをリポジトリに複製する案は、資産の権利・サイズ・更新元を混同するため採用しない。CLIが任意のローカルディレクトリを読む形にする。

## Constraints / Gotchas

- `lossless` は単一フレームが予算を超える場合にも可逆出力を返す契約なので、`withinBudget: false` は変換失敗ではない。CIで予算を必須にしたい場合だけ `--require-within-budget` を指定する。
- `astral_opening` は30フレーム・96x32・全体436色で、frame 13/14 がそれぞれ9,658/9,516文字となる。losslessの合計97,294文字・30スクリプトは、CLIで検出・回帰監視する基準ケースである。
