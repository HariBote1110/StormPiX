# 列辞書の境界符号化

## 決定

- 可変長の列パターン配列 `q={"…","…"}` を、パターン内部に現れない `!` で区切る単一文字列 `q="…!…"` に変更した。Lua デコーダは参照番号まで走査して該当するパターンを取り出す。
- 辞書の分割は script load 時に一度だけ `Q` table へ行い、`onDraw` は `Q[n+1]` を参照する。実 Lua で2,400フレームを測ると、旧scan形 0.214085 ms/frame に対して index形は0.113428 ms/frame だった。同じハーネスの draw call 数は1,407,360で不変である。
- 実資産40フレームでは index形が5,530文字となった。走査デコーダ形の5,536文字より6文字短く、5,895文字からは365文字減である。

## B2 の計測

- 1回利用82件をストリームへ inline 化する案は、元の配列辞書を基準にデータが328文字減るが、縦run合計が高さに達するまで読む安全な分岐が343文字増える。単独では +15文字（5,910相当）である。
- B1後に同じ案を組み合わせると、辞書境界とinline escapeが相殺するため、参照節約164文字に対してデコーダが336文字増える。結果は +172文字である。
- よってB2は採用しない。B1は単独で目標を満たしたため、より複雑なinline形式は実装しない。

## 制約

- `!` はパターンalphabetには含まれず、参照ストリームではRLE markerである。辞書文字列内だけで境界に使うため、両方の意味は衝突しない。
