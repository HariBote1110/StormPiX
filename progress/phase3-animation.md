# Phase 3アニメーション変換の設計判断

## Decision

- フレームを縦連結した画素列に対して一度だけ量子化し、共有パレットを全フレームで使う。これによりパレット定義をフレーム数だけ繰り返さない。
- 既存の矩形被覆に透明な `changed` マスクを拡張し、フレーム 0 は完全描画、以降は前フレームから変化した矩形だけを出力する。
- 全フレーム形式とキーフレーム＋差分形式を、既存の direct/table/packed emitter で実際に生成して比較する。差分の packed 形式は透明画素を表現できないため、そのフレームだけ table emitter にフォールバックする。
- ループの seam は、フレーム 0 の完全描画をフレーム分岐に残す方法を採用した。wrap 時にフレーム 0 が実行されるため、最後の状態を確実に上書きできる。
- `rendered` は最初の量子化フレーム、メトリクスは全フレームの平均とする。アニメーション専用の統計は既存 `ConvertStats` に任意フィールドだけを追加した。

## Alternatives considered

- 差分の循環チェーンは、開始時だけ完全フレームを別に保持する必要があり、生成分岐が増えるため採用しなかった。
- フレームごとのパレットは、パレット定義を繰り返して共有予算を圧迫するため採用しなかった。
- 疎な差分を packed の黒背景付き矩形として出す方法は、未変更画素を黒で上書きするため採用しなかった。

## Constraints / Gotchas

- フレームは空配列を許可せず、全フレームの寸法を一致させる。
- `ticksPerFrame` は 1 以上の整数に正規化し、Lua は 60Hz の `onTick` からのみフレームを進める。
- アニメーション探索では候補ごとに SSIM/PSNR/RMSE と実測 Lua 長を評価するため、既定の探索時間は 5000ms とする。
