# Phase 5 ロスレス複数スクリプト

## 契約

既定モードを `lossless` とし、入力のRGBA画像から得た全てのRGB色をそのまま使う。`fit` はPhase 1〜4の探索をそのまま使う互換経路で、既存ベンチと既存テストは明示的に `mode: 'fit'` を指定する。lossless結果は `scripts`、`totalCharCount` を持ち、`lua` と `charCount` は従来どおり先頭スクリプトだけを指す。

## 分割判断

単一画像は矩形描画レコードの連続範囲を候補とし、各候補のdirect/table文字数を計算して動的計画法で「合計文字数、同点ならスクリプト数」を最小化する。アニメーションはフレーム範囲を候補とし、範囲先頭を必ずfull frameにしてから差分を続ける。これによりスクリプト境界で差分の依存が切れず、各スクリプトが独立して再生できる。

## kamishibaiから得た機構

`FinalizeLuaCode.ts` の `standardFinalize` はカードごとに長い初期化を繰り返さず、`R(x,y,w,h)` を一度だけ共有し、各カードを短い `if I==... then` ブロックとして連結する。こちらはlossless専用のcompact emitterで未使用aliasを出さず、グレースケール palette helperを一度だけ置いた。さらに矩形を `x/y/w/h/colourIndex` の30bit固定レコード（5文字）へ可逆に符号化し、各スクリプトに一度だけデコーダを置く。これはgamma変換ではなく、元の色値をそのまま復元する。

この矩形ストリーム候補と通常のcompact direct候補を各フレーム範囲で比較し、最短のものを動的計画法へ渡す。実アセットはlosslessで4/8/16/24/40フレームがそれぞれ587/1205/3539/5875/11429文字、40フレームは2スクリプトになった。

## 検証上の注意

生成された全スクリプトをLua 5.5で個別実行し、アニメーションでは `scriptFrameRanges` の担当範囲、単一画像では全スクリプトの描画操作を合成して原画像と比較する。通常の矩形入力ではlossless SSIMは厳密に1である。Lua実行器は既存どおり差し替え可能な小さい境界に保つ。
