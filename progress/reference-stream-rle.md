# 列参照ストリームの可逆RLE

## Decision

- 実資産の列辞書におけるフレーム参照列だけを、隣接して同じ列IDが続く場合に可逆RLE化した。予約した`!`の後ろに既存64文字alphabetの実行長を置き、短くなる実行だけを採用する。
- 高位列IDのalphabetから予約文字を外した。既存の1文字・2文字ID形式と自己完結したLuaデコーダは維持している。
- `pnpm bench` は40フレーム実資産の文字内訳を恒久出力する。内訳は alphabet、palette、辞書、参照ストリーム、helper、再生分岐で、合計と一致する。

## 測定

実装前後の40フレーム・lossless・8192文字予算の内訳は次のとおり。

| 区分 | 前 | 後 | 差分 |
| --- | ---: | ---: | ---: |
| alphabet | 99 | 103 | +4 |
| palette | 44 | 44 | 0 |
| 辞書 | 3,329 | 3,329 | 0 |
| 参照ストリーム | 3,167 | 2,030 | -1,137 |
| helper | 610 | 722 | +112 |
| 再生分岐 | 730 | 730 | 0 |
| 合計 | 7,979 | 6,958 | -1,021 |

同資産には2,560列のうち隣接同一列に属する列が1,500あり、RLEデコーダの112文字を十分に回収する。Lua往復で全40フレームのRGBAが完全一致した。

## Alternatives considered

- 固定幅参照をエントロピー符号化する案は、列IDのエントロピーが約5.08 bitである一方、codebookとLuaビットデコーダの固定費が必要になるため、この小さな変更より先に実装しない。
- パターンの二段辞書は、現行辞書本体が3,329文字で変化せず、測定で大きい未利用反復が参照列の隣接実行に偏っていたため見送った。
- 移動検出、非矩形primitive、画像の品質低下は契約・測定の両面から対象外とした。

## Constraints / Gotchas

- `!`は参照RLEの予約文字であり、高位ID alphabetへ戻してはならない。
- 高位IDは2文字なので、LuaデコーダはID全体を消費してからRLE markerを読む必要がある。この順序を誤ると見た目はもっともらしいまま列がずれるため、実資産のLua往復テストを必ず維持する。
