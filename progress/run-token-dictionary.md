# 縦runトークンの第2辞書

## Decision

- 列パターンを直接の`colour/run-length`対で保存する代わりに、全列で共有するrunトークン辞書を追加した。頻度順の76種類のrunを2文字ずつ一度だけ保存し、各列パターンは既存の`A`/`H` alphabetを使う1文字IDで参照する。
- 実資産では1,344 runトークンが76種類しかない。従来のパターン内容2,688文字を1,344文字へ半減でき、プールとデコーダの追加費を実測で上回る。
- `pnpm bench` の実資産内訳には、辞書エントリ数、符号化パターン文字数、構文文字数、run種類数・プール文字数、1回・2回利用エントリ数とそのパターン文字数を恒久的に出力する。

## Measurement

変更前の列辞書は212エントリ、パターン内容2,688文字で、長さは2文字が1件、6文字が2件、10文字が138件、18文字が69件、26文字が2件だった。82エントリ（932文字）は1回だけ、2エントリ（36文字）は2回だけ参照される。

エントリ全体が他のエントリの部分文字列である件数は0だった。一方、2文字のrunトークンは1,344出現中76種類しかなく、最頻値は266回出現する。この局所的な重複を第2辞書として共有した。

## Alternatives considered

- エントリ全体を共有文字プールへ連結する方式は、完全な部分文字列が0件であり、offset/length表の固定費を回収できないため不採用とした。
- 1回利用エントリのinline化は、列ID参照より短くするには呼び出し側とデコーダの別形式が必要で、212エントリの共通run化より小さい見込みだったため不採用とした。1回利用のrunは他エントリと共有される。
- エントリ順のdelta符号化は、共有prefix/suffixは短いrun単位に集中し、差分の位置・長さを表す費用がrun辞書より高いため不採用とした。

## Constraints / Gotchas

- Luaのrunプール名`B`を`for r=...`の反復変数と同名にしてはならない。Luaはその反復変数を優先し、部分的な描画だけを行う。
- run IDは76種類であるため、`A`の64文字に加えて`H`の先頭12文字を使う。高位IDを読む経路は列IDの高位参照経路とは別に維持する。
